# 财税 Agent Harness（赛题二）

一个能**查金额**、**补发票用途**、**多轮接着办**的财税助手。核心不是让模型更聪明，而是把会犯错的模型放进不会犯错的流程里。

> **状态**：主链路已可运行（查询 / 检查 / 保存 / 恢复 / 审计 / 记忆 / 规则版本选择），24 条陷阱测试全绿。
> 未完成：长对话自动摘要、Web 界面（当前是命令行入口）、复赛新数据适配。

---

## 快速开始

```bash
# 1) 装依赖（Python 3.11+）
pip install -r requirements.txt

# 2) 一键演示（不需要模型 Key）
python demo.py

# 3) 跑陷阱测试
pytest -q          # 24 passed

# 4) 命令行操作入口
python -m harness.cli
```

数据库 `data/harness.db` 会自动从官方 Excel 生成；`python demo.py` 每次运行会重置到初始数据。
接模型见文末「五、接入模型」。

## 三、模型与程序的边界

这是评分维度二（25%）真正看的东西，一句话：**模型负责理解和决定，程序负责计算和裁决。**

| 环节 | 谁做 | 为什么 |
| --- | --- | --- |
| 理解用户说的这句话 | 模型 | 规则写不出来，关键词匹配被赛题明确禁止 |
| 决定先查数据还是先追问 | 模型 | 需要结合上下文判断 |
| 把结果说成人话 | 模型 | 语言质量 |
| 金额求和、按方向分别统计 | 程序 | 模型算数会错，且必须可复算 |
| 判断该用哪版规则 | 程序（`policy.py` + 数据库生效日期） | 模型会拿旧版算新账 |
| 用途是否必填、门槛多少 | 程序（常量表） | 政策参数不能进提示词 |
| 能不能保存、能不能改这个字段 | 程序（`tools.save_patch` 五项校验） | 模型没有第二个入口 |
| 说「已保存」 | 程序（回执） + 中间件守门 | 无回执不得声称完成 |
| 语气自然 | 程序（`style.py` 7 条规则） | 能测的才叫保证 |

代码里对应的一句话总结：**模型只能提议调哪个工具、填什么参数，不能执行、不能改校验、不能加权限。**

## 四、官方 7 项要求 → 代码位置

| 官方要求 | 实现 | 位置 |
| --- | --- | --- |
| 1 对话与决策 | Agent 主循环 + 系统提示（模型驱动，无关键词分支） | `agent.py` / `context.SYSTEM_PROMPT` |
| 2 记忆管理 | `memory` 表 CRUD + 按企业/用户隔离 + 单未完成任务唯一索引 | `memory.py` |
| 3 知识库管理 | `(doc_id, version)` 主键 + `status` + 生效日选择 + 检索 | `policy.py` |
| 4 模型输入 | 7 段装配 + 预算裁剪 + 永不裁剪项 | `context.py` / `middlewares.ScopeMiddleware` |
| 5 数据操作 | 五项校验 + 三态回执 + 幂等键 + 部分唯一索引 + 保存后重查 | `tools.save_patch` |
| 6 运行记录 | `audit_event`（只追加）+ `tool_log`（参数/结果/耗时/回执） | `audit.py` / `tools._track` |
| 7 自然表达 | 7 条确定性规则（套话/结论前置/列点/无回执/空转/长度） | `style.py` |

加分项：长对话摘要 **未做**；变更后仍正确（规则换版、记忆改删、切企业）**已可验证**；重启恢复 **已做**（`get_save_result`）；对比实验 **未做**。

## 五、接入模型

```bash
cp .env.example .env      # 填 BASE_URL / API_KEY / MODEL（任意 OpenAI 兼容接口）
python -m harness.cli --llm
```

模型侧只多一行：`create_agent(model, tools, system_prompt, middleware=[...], checkpointer=...)`。
同一套工具、同一套校验，只是由模型决定调用顺序。没有 Key 时 `agent.py` 会给出明确提示，不影响 `demo.py` 与测试。

## 六、几个关键实现选择

1. **金额用整数「分」**。官方汇总表本身就出现了 `9622.060000000001` 这类浮点尾差，用 float 做相等判断必然出错。
2. **幂等键 + 部分唯一索引双保险**。`UNIQUE(company_id, idem_key) WHERE status='success'`，应用层写错也重复保存不了。
3. **保存后重新查询核对**。返回的是库里真实值（`saved`），不是调用方传的 patch；不一致直接标 `VERIFY_MISMATCH`。
4. **规则版本由日期决定，不由模型决定**。8 月没有现行规则，`missing_purpose` 返回 `not_applicable` 并说明原因，而不是硬套 1.0 版。
5. **未完成事项永不裁剪**。上下文压到极限时，Agent 仍知道手里还剩哪几张票。
6. **去 AI 味是代码不是提示词**。可写单测断言黑名单命中为 0，模型做不到。

## 七、与 GitHub 参考项目的关系

「harness」已是成熟品类（如 `langchain-ai/deepagents` 用 LangChain+LangGraph 做 agent harness），通用职责划分是 **模型接入 / 工具分发 / 安全层 / 会话记忆 / 可观测性 / 扩展点**，本项目按这个骨架组织。

发票类开源项目（如各类 invoice agent）几乎都集中在 **OCR + 字段抽取 + RAG** —— 而本题数据已经是结构化 Excel，**不考 OCR**，真正的难点是权限、幂等、版本化规则和可审计。这部分没有现成项目可抄，是本项目的主投入。

## 九、打包（分发 / 提交用）

```bash
python scripts/package.py          # 生成 dist/tax-agent-harness-v0.1.0.zip
python scripts/package.py --no-rebuild   # 不重建数据库，直接用现有库
```

脚本会依次做四件事：清理缓存与临时文件 → 从官方 Excel 重建干净的 `data/harness.db` → 按白名单收集文件 → 生成 zip 并打印清单、大小与 SHA256。

**不会进包**：`__pycache__`、`.pytest_cache`、`.pytest_tmp`、`.env`（只带 `.env.example`）、SQLite 的 `-wal/-shm`、`.workbuddy`。

**解压即用**：包内 `data/harness.db` 是重建后的初始数据，解压后无需再跑导入脚本，`python demo.py` 与 `pytest -q` 直接可用。即使解压工具改坏了中文目录名，导入脚本会按文件内容定位 Excel，仍可重建。
