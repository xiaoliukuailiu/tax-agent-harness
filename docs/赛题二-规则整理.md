## 1. 问题背景（原文要点）

财税业务中很多任务需要连续处理，而不是一次对话完成。例如：用户先让 AI 查询某家企业的发票和银行收支，再检查信息是否完整；若某张发票缺少"用途"信息，AI 需要继续询问用户，并在信息补充后完成保存。

这类多轮任务中 AI 的典型失败：
- 忘记前文
- 用错旧规则
- 混淆企业信息
- 说"已保存"却没有真正完成操作

赛题要求：把**任务记忆、规则文档、程序工具**结合起来，让助手能接着办事、核对结果、留下操作记录。主办方提供简化规则和模拟接口，**无需财税专业知识**。

## 2. 三个场景（共用同一套任务处理流程）

1. **发票与银行查询**：查询数据、匹配规则、解释填写要求
2. **补充信息并保存**：校验对象和修改内容，完成保存并确认结果
3. **多轮检查**：保留上下文和未完成事项，支持连续处理

**自然表达（去 AI 味）**，原文：
> 回复像日常交流：先说结果，语言简洁，按需解释；少套话、少重复，不机械列点。不确定或未完成时直说，不编造结果。

## 3. 基础任务（必须完成）

| # | 任务 | 要求原文要点 |
| --- | --- | --- |
| 1 | 统一运行 | 根据任务和当前结果，选择查规则、调工具、询问用户或结束任务；三个场景共用同一流程 |
| 2 | 记忆管理 | 记住任务进度和用户明确提出的长期偏好；**支持查看、更正和删除**；不混用不同企业、用户的记忆 |
| 3 | 知识库管理 | 支持**添加、查找、更新和停用**规则文档；回答注明所用文档及版本；依据不足时明确说明 |
| 4 | 上下文管理 | 挑选本次交给模型的对话、记忆、规则和工具结果，控制长度并保留企业、月份和未完成事项 |
| 5 | 工具执行 | 修改数据前检查企业、对象、内容和权限；核对保存结果并区分**处理中、成功、失败**；避免重复操作 |
| 6 | 过程可检查 | 记录工具调用及结果、所用记忆和规则来源；缺信息或操作失败时，说清原因和下一步 |
| 7 | 自然表达 | 先说结果，语言简洁，按需解释；少套话、少重复；不确定或未完成时直说，不编造结果 |

> 原文约束：**基础任务限少量数据、一个 AI 助手和顺序操作。** 优秀作品不只是调用工具，而是让 Agent 稳定完成连续业务任务。

## 4. 进阶挑战（加分项）

1. 将长对话整理成摘要，保留关键信息和未完成事项
2. 更正记忆、更新规则、切换企业或修改数据后，仍能正确处理
3. 工具超时或程序重启后恢复任务，先查上次结果，避免重复保存
4. 用对比测试说明不同记忆、检索和模型输入方式对**正确率、耗时和调用费用**的影响

## 5. 提交物

1. 一个可运行的财税 Agent Harness 运行系统
2. 源代码、运行环境与启动说明
3. 简要设计说明：记忆、规则文档和工具如何配合
4. 操作入口：网页、命令行或接口，能运行任务、查看结果和**操作记录**
5. 演示 Demo：展示**真实保存结果**和自然对话回复

## 附：评审视角的三个信号（整理者注）

1. **"说已保存却没保存"被点名为头号失败模式** → 工具执行的三态确认与幂等是硬门槛，Demo 必须展示真实落库结果。
2. **"自然表达"在挑战描述和基础任务里各出现一次** → 是明确的评分暗线，建议做成输出后处理层而非只靠 Prompt。
3. **"模型和规则的边界是否合理"** → 对应设计文档里的核心主张：查数/计算/校验交给代码，模型只做理解与决策；答辩时这是最值得讲的取舍。
